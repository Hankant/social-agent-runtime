# 跨框架执行合同

## 任务、调度和提交

逻辑决策键至少区分实验配置、模型与参数、prompt/协议版本、观察及记忆哈希、agent、轮次。一次逻辑决策可以有多个物理API尝试，编号分开。成功缓存需校验完整身份和结果合法性，不能仅按agent/tick命中。

使用有界滚动队列，完成一项即补一项；避免每组N个等待最慢项再发下一组，也避免一次提交全体任务。线程上限、实际在途数、供应商RPM/TPM/连接池和派发间隔分别记录。有界线程不自动等于有界请求：SDK重试、路由和并行工具可能再产生请求。

线程输入为独立快照；共享预算和编号在锁/事务中更新。CPU密集工作评估进程或其他方案，不承诺线程提升CPU效率。异步SDK保留异步实现并用有界信号量。

全局错误后停止新请求，尽可能收尾并持久化在途结果。Python不能安全强杀运行中的线程；必须配置连接/读/写/连接池超时。强制终止后未确认的请求保留为结果未知，不能假记失败免费重发。

## 持久化与恢复

- 发请求前持久化任务身份、尝试编号、预算预留及pending记录。
- 收到响应先存原始响应和usage，再存校验状态；成功缓存持久化后才可报告完成。
- 完整轮次提交使用事务或带hash的原子检查点；临时文件与完整断点分开。提交后导出失败不得抹掉主状态或原始错误。
- 恢复读取完整父子链，继承成功缓存、已耗尝试、预算、下线记录、门控状态和随机数状态；不能重置失败次数获得无限重试。
- 同一状态快照对比包含模型/协议/代码/配置hash；工程迁移写入明确允许的父运行、前后hash、测试和变更范围，不用通配符绕过检查。
- 进程锁在入口实现，检测PID/启动时间/命令身份，避免PID复用。running状态文件不证明进程活着。多主机使用适当分布式锁。
- exactly-once应用由幂等提交实现；网络API通常不能保证恰好调用一次。未决请求只有在供应商可核验去重/取回，或用户明确接受重复调用风险后再处理。

## 错误分类

| 类别 | 建议行为 |
|---|---|
| 输出截断、空内容、JSON/字段错误 | 有限格式再生成；保持相同观察，添加精确结构反馈；保存所有尝试 |
| 行动越界/不可见对象 | 校验器拒绝或依合同处理，不能自行编造合法对象 |
| 已执行的重复子行动 | 依动作合同幂等；若允许部分提交，只拒绝该子行动，记录原答和执行答 |
| 429/服务繁忙 | 根据官方文档和安全响应元数据分类，有限全局门控、派发节奏和Retry-After；不凭状态码判余额耗尽 |
| 连接前失败 | 根据是否已发出和供应商语义有限恢复 |
| 请求发出后超时/进程终止 | 标记结果/usage未知，查取回或幂等能力；不盲目重发 |
| 鉴权、明确额度、硬预算 | 全局暂停并报告，不切换付费方式或替换模型 |
| 磁盘/PermissionError/日志提交失败 | 全局工程故障；检查路径、锁与提交一致性，不能技术下线某人 |
| 个人有效决策耗尽 | 按事先研究合同处理，记录失败类别和剩余人数，不伪造回答 |

区分结果未知和仅usage未知：有完整已校验响应但无usage，不必重新生成；预算保持保守预留。未知状态/新供应商错误先暂停分类，不直接归入个人失败。

## 限流与恢复

参数化退避、抖动、重试总额、RPM/TPM、初始/最小/最大并发、派发间隔、恢复成功次数及稳定时间。历史2/4/8/16/32/60秒仅是可选起点，不能当供应商通用要求。更长Retry-After优先。

同一波并发拒绝聚合为一个全局拥堵事件；避免每个线程分别减半，把10瞬间压到1，也避免各自重置退避序列。记录事件ID及失败数。529等过载不能证明客户端并发过高。

稳定成功一段时间后逐级增加并发，限流后重置恢复计数；“成功”取新增合法决策，不取HTTP200、缓存重放或JSON失败。用有效吞吐量检验恢复，不为凑线程数猛增。多key只有在用户授权且供应商允许独立额度时路由，不能假设配额独立或用于绕过限制。

## 台账与日志

记录run/parent、agent、tick、decision_key、attempt、request_id、代码与配置hash、模型、请求参数、派发/完成时间、队列/门控等待、在途数、有效并发、HTTP/服务码、错误类型、finish_reason、校验原因、缓存命中、输入/输出/缓存/推理token、usage来源、状态转换、断点hash。

预算预留是本地保护，实际usage是供应商测量，费用需另有价格及计费依据；bytes和其他tokenizer估算不能标为供应商token。输出max_tokens是上限，不是已消耗。缓存token可能是输入的子集，不能重复相加。先查SDK默认重试，全部实际调用纳入账本；供应商/SDK隐式尝试不可见时明确统计缺口。

安全诊断保存白名单码、类型、耗时、request_id和经筛查的错误摘要，不全量打印异常头/URL/请求体。审计记录保留原始模型输出与执行修正的关系。
